# Rabbit Hole · Word Web

Open `/word-web` by direct URL. There are no incoming app links. Run `npm run start:frontend` and `npm run start:app-server` for a local preview at `http://localhost:3001/word-web`.

## Private access

In production, every route entry or refresh starts locked, including browser back/forward cache restores. Enter an email and the shared password, and select the same account using Google sign-in. The server validates the Google ID token's signature, issuer, audience, expiry, verified email, and page nonce. It checks both the exact server allowlist and the password before releasing the application. There is no persistent authentication flag or automatically restored login.

Local `npm start` / `npm run start:frontend` development opens Word Web automatically without email, password, Google sign-in, or a running backend. CRA loads the `src/setupProxy.js` middleware only in its development server; it serves the private bundle to loopback connections from localhost origins only. The production backend and Netlify function do not implement this endpoint. The browser's development request is removed during production compilation, and the build checks that it is absent. Deploy previews also use the production login. No query string, localStorage flag, or request header enables a production bypass. Restart the frontend server after changing its middleware.

Manage approved addresses in `server/wordWebAccessPolicy.js`, then restart/redeploy. The password check exists only in `server/wordWebAccess.js`. Never move it into React, a `REACT_APP_` variable, or a public file. Credentials are sent in a POST body and are not logged or persisted by the app.

Google client ID: set `WORD_WEB_GOOGLE_CLIENT_ID` or reuse `GOOGLE_CLIENT_ID`. Add the preview/production origins to that OAuth client's Authorized JavaScript origins in Google Cloud, including `http://localhost:3001` for local development. Set `WORD_WEB_CHALLENGE_SECRET` to a random server secret of at least 32 characters; the existing `CQUIZ2_SESSION_SECRET` is also supported with purpose-separated signatures. Production fails closed if configuration is missing. Local development reads `.env.local` without exposing its contents. Custom backend hosts must set `WORD_WEB_ALLOWED_ORIGINS` to a comma-separated list of exact frontend origins; Netlify's own URL environment variables are recognized automatically. Use HTTPS in production.

`npm run build:word-web` creates an independent JS/CSS bundle in `.word-web-private/`, outside the public `build/` directory. `npm run build` also checks that the public JS/source maps do not contain the explorer implementation. Never import `src/WordWeb` into the public app, publish `.word-web-private`, or serve it statically. `npm run watch:word-web` rebuilds private app changes during development; sign in again to load them.

The same access handler is used by the local Node backend and the Netlify function at `/api/word-web/*`. Private code is returned only by authenticated POST, with no-store CDN/browser headers. GET, altered browser state, forged/unverified Google tokens, unknown accounts, expired/tampered challenges, and wrong origins cannot retrieve it. Attempts are limited on the local backend and by Netlify's distributed function limit.

This controls delivery to unauthenticated visitors. An authorized browser can inspect/copy downloaded code or its own local graph; no password gate can prevent that. Public dictionary providers remain public services. Previously deployed public builds and code already cached by earlier visitors cannot be recalled by this change.

Access tests: `npm run test:word-web-access` and the `src/WordWebAccess` React tests. A real Google popup requires interactive sign-in and correctly configured Google Cloud origins.

Click an underlined vocabulary word in the centered definition, or a synonym or antonym, to discover a node. Common stop words (such as “a”, “to”, “not”, and “the”) stay plain text and do not trigger lookups; matching ignores capitalization and handles curly apostrophes in contractions. Multiword vocabulary phrases remain explorable. The camera follows the current word. Click any canvas word once to inspect its immediate connections and neighboring words in orange, including words outside the current trail or beyond the forward limit. This changes only selection. Click the selected word again to follow an available connection, or to backtrack when it is blue. Connection lines and breadcrumbs retain their direct actions.

The trail is the active, non-repeating path from the root to the focused word. Its complete list of breadcrumbs is horizontally scrollable. Click any earlier breadcrumb, or click its blue canvas word twice, to return there and remove every later step; subsequent exploration adds a new suffix. Back pops exactly one step. A second click on a selected blue canvas word can backtrack to any earlier active-path step, even without a direct connection or when the forward trail limit is reached. References to active-path words remain disabled in definitions, synonyms, antonyms, and line controls. Incident connections that would repeat a trail word are purple and dashed. After leaving a branch, its words can be revisited through valid connections, including newly discovered cross-links. Known base-word aliases obey the same lock. Blocked clicks are rejected before dictionary requests, and newly resolved aliases are checked again before graph mutation.

Definition edges are single thick gray strokes without an outline. Synonym edges are green; antonym edges are red. Automatic cross-links start at 20% opacity. After a particular relationship is traversed, its connection becomes a thin, bright white line at full opacity. Multiple relationships between a pair are drawn separately and can be selected by their lines.

Canvas word labels grow by 3pt for each incident connection, including discovered and walked definition, synonym, and antonym relationships. Each relationship counts once at each endpoint; parallel relationship types count separately. A memoized degree map and adjacency sets are built together in one O(edges) pass. They support O(1) size lookup and direct neighbor lookup for selection, without rescanning definitions. The base font size is 19px on desktop and 15px on mobile; existing node coordinates stay fixed.

The active path uses blue lines and a blue glow on the exact relationships used; its words remain blue for backtracking. Orange selection temporarily emphasizes all incident relationships (including faded ones) and their adjacent labels; the blue trail glow stays visible. Clicking empty canvas space or pressing Escape clears the selection. Back removes that step's glow, while previously walked connections remain thin and bright white. Saved webs include `trailEdges` so parallel relationships are highlighted correctly. Older chronological histories are converted to a loop-erased active path without moving words or clearing walked edges.

While the current definition is minimized, its dock also shows the selected word in an orange label immediately to the left of the blue current-word button. The two labels stay side by side on small screens, above the zoom controls.

The connections-walked stat displays unique traversed relationships out of total discovered relationships (for example, `47 / 74`). Backtracking does not reduce that count, and walking the same connection again does not increase it. It is visible on small screens as well as desktop.

New webs can freely establish their first discovery branch. The first backtrack enables the trail limit. Thereafter, when the active trail has at least as many steps as the longest discovery branch, both new-word discoveries and forward connections are blocked. Breadcrumb backtracking and starting an independent New web remain available. Older saved webs adopt the limit immediately; brand-new single-word webs are exempt from the zero-length deadlock. The limit's active state persists in `trailLimitActive`, including across base-word migration. New webs share dictionary caching, not graph or trail state.

## Structure and indexing

`graph.ts` stores a rooted discovery tree (parent pointers and depth) separately from the cyclic semantic graph. Adjacency sets restrict traversal. A token trie stores discovered words, including phrases. Reverse-reference tries store definition-token postings and exact synonym/antonym postings. Inserting a word queries existing references, then scans only its new definitions against the word trie. Phrase queries intersect token postings and confirm word order and boundaries. Content comparisons do not scan every stored definition.

Navigation uses an array stack of word IDs and exact edge IDs plus a hash map of trail positions. Membership checks, append, and pop are O(1), excluding snapshot rendering. Breadcrumb backtracking looks up its destination in O(1) and removes k later steps in O(k). Migration loop-erases old histories in O(history length), plus adjacency lookups. The discovery tree caches `depth(child) = depth(parent) + 1` and its running maximum, so updating and reading the longest discovery branch are O(1). This metric is the longest root-to-leaf discovery branch; it is separate from the longest simple path across all semantic shortcuts.

Inflected forms share a canonical dictionary headword: `sugars` → `sugar`, and `ran` / `running` / `runs` → `run`. `wordForms.ts` uses explicit dictionary inflection references and grammatical form lists, rather than stripping suffixes. The word trie and reverse indexes recognize known variants for definition, synonym, and antonym links. Clicking a form of the current word does not create a node or self-loop. Independent headwords and derived words such as `glass` and `healer` remain separate.

Opening or importing an older web merges duplicate forms into the canonical node, preferring an existing base entry and retaining its world coordinates. Connections and traversal flags are combined, self-loops removed, and consecutive duplicate history steps collapsed. The surviving nodes stay in place. Old definition references are retained internally so previous connections remain valid; the card shows the base entry's definitions. If the saved web contains only an inflected entry, its real base definition is fetched when that node receives focus.

`layout.ts` keeps every node and edge in fixed world coordinates. A single camera transform pans the entire world to center the focused word; it never rotates, clamps, or rearranges individual nodes. Nodes and lines animate together in one layer, and edge curves keep their shape when focus changes. Zoom uniformly scales the world. The definition card stays centered above it. Nodes may extend offscreen as the web grows; zoom and fit change only the camera, not the graph or traversal status.

The Minimize word control beside zoom docks the current word into a restore button and exposes its label on the canvas. With the card minimized, drag the canvas with a mouse, pen, or finger to pan; keyboard users can focus the canvas and use arrow keys. The camera stores pan in world units so changing zoom retains the inspected map center. A drag threshold and click suppression prevent accidental traversal when dragging over a word or connection. Pointer cancellation releases the gesture. Restore (or Escape), following a connection, breadcrumb backtracking, and starting/importing a web return to the centered definition. Fit resets the manual offset while keeping the card minimized. These view changes do not modify the graph, trail, walked count, saved coordinates, or dictionary cache.

## Dictionary and persistence

The primary API is [FreeDictionaryAPI](https://freedictionaryapi.com/api/v1), with [dictionaryapi.dev](https://dictionaryapi.dev/) as a fallback. Neither requires an API key. Definitions and relationships come from the provider, including nested senses. Entries retain source and Creative Commons attribution. Dictionary coverage varies; missing synonyms or antonyms are shown explicitly. Definitions are requested only when clicked, and concurrent requests and successful results are cached.

The explorer displays provider and license attribution as plain text. Source-article, provider, license, and All apps navigation links are omitted from its UI so vocabulary exploration stays within the dictionary screen. Source and license URLs remain in dictionary metadata and JSON exports.

An uncached inflected word can require a lookup of the spelling and then its base entry. Later clicks on known variants reuse the same cached base entry. Concurrent requests for different variants share the base lookup; dictionary-reference cycles fail cleanly.

`starterEntries.ts` contains seven real entries cached from Wiktionary via FreeDictionaryAPI, including the starting word “curiosity”. Refresh with `node scripts/refresh-word-web-starters.cjs`. All other uncached words require an internet connection. Failed lookups leave the current graph intact and offer retry.

The entire graph, entries, positions, and walk are saved under `rabbit-hole-web-v1` in localStorage. The app displays save failures and supports JSON export/import. Imported webs are validated for tree structure, relationships, and a continuous walking trail before replacing the current graph. Starting a new web replaces the saved web only after a successful dictionary lookup.
